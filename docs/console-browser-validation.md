# 当前控制台的隔离浏览器验收

测试使用当前前端路由、表单及真实后端 API，不挂载独立测试页，不拦截 HTTP 返回模拟保存结果。后端 fixture 仅创建隔离 SQLite、管理员测试会话、离线机器人和三份发布声明（两份已安装、一份未安装）；不连接业务执行机，不覆盖现有服务配置，也不运行导出。

## 重复执行

终端一启动隔离后端，目录必须不存在；每次演练使用新的目录：

```sh
uv run --project apps/backend python apps/backend/tests/console_fixture.py --directory /tmp/rpa-console-browser-check
```

终端二启动当前控制台，API 指向隔离端口：

```sh
RPA_API_TARGET=http://127.0.0.1:4191 pnpm --filter @rpa/web dev --port 4190
```

终端三使用可用的 Playwright 运行时执行浏览器脚本；已有 Playwright 包可以通过 `PLAYWRIGHT_MODULE_PATH` 指定绝对路径。可用 `CONSOLE_BROWSER_SCREENSHOT` 指定截图文件：

```sh
node apps/web/tests/platform.browser.cjs
```

脚本只允许回环地址，使用测试专用会话。结束后关闭前两个终端的进程；不要把 fixture 作为测试服务或正式服务的启动入口。飞书真实登录与角色隔离另行验收，不能以 fixture 会话证明企业登录通过。
